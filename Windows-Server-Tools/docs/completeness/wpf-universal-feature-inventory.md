# Primary WPF universal-feature inventory

## Evidence boundary

This hand-written inventory covers both user-facing WPF windows in the primary application:

1. `MainWindow` in `Windows-Server-Tools/Windows-Server-Tools/MainWindow.xaml`;
2. `CommonlyInstalledWindowsComponents` in `Windows-Server-Tools/Windows-Server-Tools/CommonlyInstalledWindowsComponents.xaml`.

The inventory was created against the WPF source contained by `origin/main` commit `2732fe8e9078f492e3c07ec0ccd943fb97cab50a`. Existing recovery behavior is linked where it exists. A source reference alone is not built-artifact proof, and no historical test, package, or capture is treated as current evidence.

Status meanings:

- `READY`: implementation, documentation, localized copy, persistence where applicable, focused tests, built-artifact interaction, and a real capture are all current and linked.
- `PARTIAL`: some implementation exists, but one or more required evidence columns are absent.
- `MISSING`: the contract is not implemented on one or both WPF windows.
- `DOCUMENTED-NOT-APPLICABLE`: the named product capability does not exist in this application, and the row states the exact boundary.

Every `PARTIAL` and `MISSING` row blocks a release-grade shutdown. The structural verifier also fails if any stable row disappears, is duplicated, or loses a required evidence column.

## Release blockers summarized

The release-enforcement verifier must remain red until all applicable rows are `READY`. The highest-risk gaps are the original packaged icon, Squirrel.Windows updater/package route, destructive confirmation, localization and settings infrastructure, status surface, file converter, Ollama manager, local privacy-preserving user-data systems, full tab/search/appearance contracts, and real built-artifact interaction/capture evidence.

The existing recovery engine and its UI are meaningful partial implementation. They do not exempt either WPF window from the remaining application-wide contracts.
